# 演示与面试讲解

## 十分钟演示

1. 管理员登录，浏览示例课程；为新注册的教师账号授予TEACHER。
2. 学生注册，进入Java课程，阅读讲义并完成一个课时，回首页观察进度。
3. 练习一道错误选项，查看参考解析和错题本。重练答对，查看掌握状态。
4. 开始正式考试，尝试进入AI导师提问，展示后端409拦截。交卷后展示确定性分数。
5. 教师在「考试与批改」确认简答题成绩。展示AI评分与正式分数的区别。
6. 配置真实AI密钥后，导入Java集合资料；导师回答问题并展示检索来源。
7. 询问“我的薄弱知识点有哪些”，观察高层工具状态。生成学习计划并打开其中一个真实课时。
8. 教师生成练习题，展示AI_GENERATED状态，审核后才组入正式考试。

未配置AI时演示1～5与明确降级提示即可，不要展示编造的模型响应。

## 面试可以讲的设计

- 为什么选单体？业务事务和AI边界是当前重点，拆微服务会分散复杂度；模块边界保留演进空间。
- 为什么客观题不用LLM判分？确定性、可重复、低成本，模型只解释业务统计。
- 如何防越权？JWT取得当前用户，工具不暴露userId，Service查询带归属；RAG先过滤再排序。
- 为什么提示词不等于安全？防作弊、数据访问、调用预算、草稿审核全部是Java硬边界。
- 怎么避免Agent无限循环？确定性八步流程；导师工具执行器独立限制步数与批次总调用数。
- 如何处理模型不稳定？基础业务独立、AI关闭开关、有限执行器、HTTP和总体超时、统一错误、结构化校验。
- 为什么自实现小向量库？MySQL持久化让学习部署简单，课程规模受控；清楚说明精确扫描的规模限制及替换路线。
- 如何防考试重复计分？锁定当前用户行，事务内校验ExamRecord状态，提交结果持久化后重试返回已有结果。
- 如何避免学习时长乱报？心跳增量受服务器时间差和单次300秒限额约束；诚实承认不能证明用户专注观看。

“基于 Java 17、Spring Boot、Vue3 构建智能学习平台，实现课程学习、确定性考试判分、错题与知识点掌握度闭环；使用 Spring AI 接入课程RAG、工具调用、隔离聊天记忆与有界学习计划工作流，针对越权、防作弊、重复提交及模型异常设计后端校验和自动化测试。”

仅填写你实际运行和理解的功能。吞吐量、准确率、用户量、成本收益都需要真实测量，不能直接编数字。
